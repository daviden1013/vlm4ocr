    V0.7.0

    ⚠️Breaking change: PDF support is now opt-in

    If you process PDFs, you must install a PDF backend and name it. Previously pdf2image (and the poppler system binary) was installed automatically. Now a PDF package must be manually installed.

    pip install vlm4ocr[pypdfium2]      # recommended

    ocr = OCREngine(vlm_engine=vlm_engine, output_mode="markdown", pdf_backend="pypdfium2")

    If you only OCR images and TIFFs, install nothing extra — and you no longer carry a PDF dependency or its license obligations.

    Passing a PDF without a backend raises PDFBackendNotAvailableError listing the options, so the failure is loud rather than silent.

    ⚡Highlights

    Choose your PDF backend

    vlm4ocr now supports all three PDF renderers available to Python. You pick one; there is no default and no automatic fallback, so the backend you name is the backend that runs — the same PDF renders the same way on every machine.

    pdf_backend Renderer License Notes
    "pypdfium2" PDFium Apache-2.0 / BSD-3 Recommended. Permissive, wheel-only, no system binary.
    "pdf2image" poppler MIT wrapper, GPL poppler binary Requires installing poppler-utils separately.
    "pymupdf" MuPDF AGPL-3.0 Most tolerant of damaged PDFs. Review the license before commercial use. 
    pip install vlm4ocr[pypdfium2]
pip install vlm4ocr[pdf2image]   # also needs the poppler system package
pip install vlm4ocr[pymupdf]     # AGPL-3.0

    ocr = OCREngine(
    vlm_engine=vlm_engine,
    output_mode="markdown",
    pdf_backend="pypdfium2",
    pdf_dpi=200,          # default; applied identically across backends
)

    pdf_dpi is normalized, so all three backends produce the same page dimensions at the same setting. Switching backends does not silently change image size, OCR quality, or cost.

    Backends differ in what they can open. A file one backend rejects may load under another, and PyMuPDF in particular reports why a file failed more precisely (password protected vs. no readable pages) where the others can only say "failed to open". Switching backends is worth trying on a problem file — it is not a guarantee, and a genuinely unsalvageable PDF will fail everywhere.

    Errors tell you where and what

    Failures now carry structured information instead of a message buried in the OCR text. Every error says which step failed (the exception class) and what the underlying library said (verbatim, unmodified).

    from vlm4ocr import VLM4OCRError, PDFBackendNotAvailableError, DocumentLoadError, VLMError
    Class Raised when
    PDFBackendNotAvailableError No PDF backend was named, or the named one isn't installed
    DocumentLoadError The document or page could not be opened, decoded, or rendered
    VLMError The VLM call failed (connection, timeout, rate limit, auth, …)

    Batch methods (sequential_ocr, concurrent_ocr) don't raise — they record the error on the result:

    async for result in ocr.concurrent_ocr(file_paths, concurrent_batch_size=8):
    if result.status == "success":
        save(result.to_string())
        continue

    err = result.error                    # the exception object, or None
    print(type(err).__name__)             # e.g. "DocumentLoadError"
    print(err.file_path)                  # which file
    print(err.page_index)                 # which page, or None for a whole-document failure
    print(err.backend)                    # which PDF backend produced it
    print(err.original_error)             # the raw poppler / PDFium / MuPDF message
    log_to_db(err.to_dict())              # JSON-serializable for pipeline logging

    vlm4ocr deliberately does not tell you whether an error is retryable or how to fix it — that's your pipeline's decision. It gives you what you need to decide:

    # Your policy, your code: try another backend on a document that won't load.
if isinstance(result.error, DocumentLoadError):
    retry = OCREngine(vlm_engine=vlm_engine, pdf_backend="pymupdf")
    ...

# Or route encrypted files to a different queue.
if result.error and "password" in (result.error.original_error or "").lower():
    quarantine(result.input_dir)

    status remains "success" or "error" — existing code that checks it keeps working unchanged.

    One bad page no longer discards the whole document

    Previously, if a single page of a 50-page PDF failed, the entire document's results were thrown away — including pages already OCR'd and paid for. Now the successful pages are kept, and each failed page carries its own error:

    for page in result.pages:
    if page.error is None:
        print(page.text)                  # usable OCR output
    else:
        print("failed:", page.error)      # this page only

    The document's status is still "error" if any page failed, so batch code that skips failed documents behaves as before — but the good pages are there if you want them.

    Know how each page was produced

    Each page records the backend and resolution behind its image, and resize now reports actual dimensions instead of a bare flag:

    page = result.pages[0]

page.image_processing_status["page_load"]
# {'backend': 'pypdfium2', 'dpi': 200, 'size': [1653, 2339]}

page.image_processing_status["resize"]
# {'status': 'success', 'resized': True,
#  'original_size': [1653, 2339], 'final_size': [565, 800]}

    This makes runs auditable, and plot_bboxes() uses it to reload the source page through the same backend and dpi that produced the boxes, so annotated images line up exactly with what the model saw.

    Faster concurrent processing

    Page loading and image preprocessing no longer occupy VLM concurrency slots, and page loading now runs in its own thread pool instead of competing with preprocessing for asyncio's shared default pool. Large batches spend more of their time actually calling the model. Tune with page_load_workers if needed (default: one worker per CPU, capped at 32):

    ocr = OCREngine(vlm_engine=vlm_engine, pdf_backend="pypdfium2", page_load_workers=16)

    CLI

    vlm4ocr --input_path docs/ --vlm_engine ollama --model llama3.2-vision \
        --pdf_backend pypdfium2 --pdf_dpi 200

    Web application

    The backend is set in services/web_app/config.yaml and defaults to pypdfium2:

    pdf:
  backend: 'pypdfium2'
  dpi: 200

    The bundled requirements.txt pins pypdfium2, and the Docker image no longer installs poppler. If you switch backend to pdf2image, install poppler-utils in your image and add pdf2image to requirements. Batch and single-file errors in the UI now come from the structured error, so failure messages name the actual cause.

    Migration

    1. Install a PDF backend if you process PDFs: pip install vlm4ocr[pypdfium2].
    2. Pass pdf_backend=... to OCREngine / IndependentPagePipeline, or --pdf_backend on the CLI. Web app and pipeline users set it in the YAML config.
    3. Reading errors from pages[0].text still works, but prefer result.error.
    4. Catching ValueError around direct DataLoader / get_data_loader calls should become DocumentLoadError (or the VLM4OCRError base).
    5. plot_bboxes() on results produced before v0.7.0 raises PDFBackendNotAvailableError, because those results don't record which backend produced them. Re-run OCR to plot them.

    Changes

    • Breaking: pdf2image is no longer a dependency. PDF rendering requires installing one of the pypdfium2, pdf2image, or pymupdf extras and naming it via pdf_backend.
    • New: pdf_backend and pdf_dpi parameters on OCREngine, IndependentPagePipeline, and get_data_loader; --pdf_backend / --pdf_dpi on the CLI; pdf: block in the web app and pipeline configs.
    • New: exception classes VLM4OCRError, PDFBackendNotAvailableError, DocumentLoadError, VLMError, exported from the top-level vlm4ocr namespace. Each preserves the underlying library's message in original_error and chains the original exception.
    • New: OCRResult.error and OCRPage.error, both carrying the exception object, with .to_dict() for logging.
    • New: image_processing_status["page_load"] records backend, dpi, and page size; ["resize"] now includes original_size and final_size.
    • New: page_load_workers parameter on OCREngine and IndependentPagePipeline; both are now usable as context managers and expose close().
    • New: stream_ocr emits an {"type": "error", "data": ..., "error": ...} event for a document it cannot load, before raising.
    • Improved: a failed page no longer discards the rest of the document's OCR results.
    • Improved: page loading and preprocessing moved out of the VLM concurrency limit, and onto a dedicated thread pool.
    • Improved: loaders no longer print to stdout; failures are reported through exceptions only.
    • Compat: OCRResult.status values are unchanged ("success" / "error"). Error text is still written to the failed page's text for existing readers.
